# 运行时适配层契约

本工作流不绑定某个 agent 产品。要承载主代理、执行子代理和审查子代理，运行时适配层至少要提供以下映射。

## 能力映射

| 通用能力 | 运行时需要提供的具体能力 |
|---|---|
| 文件读取/修改 | 可靠读取、写入和局部编辑项目文件 |
| 命令执行 | 在指定工作目录运行 Git、测试、构建和 lint，并返回退出码与输出 |
| 隔离实现 | 在主仓库内部或明确受控位置创建/销毁 Git worktree |
| 子代理执行 | 创建独立上下文的执行子代理和审查子代理 |
| 持久状态 | 保存 task-id、阶段、branch、worktree、checkpoint、日志和阻塞原因 |
| 后台监督 | 监控活动、冻结和完成，并支持恢复或人工接管 |
| 通知 | 向用户报告完成、失败、阻塞和下一步；通知不是状态事实源 |

## 适配规则

1. 通用任务单、报告格式和验收门禁不能因为某个运行时缺少能力而被删除。
2. 运行时的命令、模型、凭据、并发限制、进程句柄和通知地址属于适配层，不写入项目产品契约。
3. 子代理如果不能真正获得独立上下文，必须把审查等级降级为“主代理自检”，不能声称是独立审查。
4. 监督器如果只能发现进程退出，不能声称它能判断业务冻结；应明确标注监督能力边界。
5. 当运行时发生重启、额度耗尽、连接丢失或通知失败时，以仓库任务单、Git、证据目录和持久状态恢复，不以旧聊天记录作为唯一事实源。
6. 适配层可以替换启动方式，但不能改变任务单冻结、独立审查、证据新鲜度和合并后复验这些工作流不变量。

## 最小降级模式

如果只具备单代理能力，可以执行：规划 → 实现 → 自检，但结果必须标记“无独立审查”，并且不能把它等同于完整工作流。只要恢复子代理能力，应补跑独立审查和主工作树复验。
