# 跨介质操作的阶段与故障矩阵

同时修改文件系统、CRDT/文档状态和 SQLite 等多个介质时，不要宣称跨介质单事务原子性。主代理须在任务单中先写阶段顺序、每个失败点、已落地的不变量和恢复路径。

## 阶段模板

1. 读源数据并计算身份或哈希。
2. 目标目录写临时文件。
3. 校验完整内容。
4. 原子重命名到最终目标。
5. 修改文档或目录候选状态。
6. 持久化文档更新。
7. 新连接中写入或重建 SQLite 投影。

## 故障矩阵

| 故障点 | 临时文件 | 最终文件 | 文档/目录状态 | SQLite 投影 | 源文件 |
|---|---|---|---|---|---|
| 源读取 | 无 | 不变 | 不变 | 不变 | 不变 |
| 临时写入 | 清理或明确残留 | 不存在/不变 | 不变 | 不变 | 不变 |
| 校验 | 清理 | 不存在/不变 | 不变 | 不变 | 不变 |
| 重命名 | 清理或记录系统残留 | 不存在/不变 | 不变 | 不变 | 不变 |
| 文档持久化 | 无 | 有效文件可保留 | 按契约保持 | 不变 | 不变 |
| 投影写入 | 无 | 有效文件保留 | 与契约一致 | 事务回滚或恢复 | 不变 |

每个故障点有独立、可重复的失败测试；注入点默认关闭且仍走真实成功算法，不用 mock 算法代替生产路径。

## 候选文档

实时文档状态不能在持久化成功前改变时：从实时状态构造候选；在候选上应用并校验变更；先按约定顺序持久化候选和投影；成功后再把候选更新应用到实时文档。

失败矩阵验证文件字节/哈希、文档状态向量或完整更新、SQLite 新连接中的精确行和源文件满足恢复不变量。

## 可恢复 worker

两个独立进程可能恢复同一任务时，内存锁不够。需要持久 owner token、租约过期时间、compare-and-set claim，以及每阶段和进度写入的 owner/lease 校验。用两个独立连接验证：租约有效时只有一个 owner 生效，过期后新 owner 可恢复。

外部上传或删除无法天然承诺跨系统 exactly-once；用稳定 operation ID 和幂等适配器，测试"外部效果完成后、状态标记前崩溃"的重试结果。
