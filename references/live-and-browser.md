# 真实浏览器、设备和多层验收边界

## 验收模式必须显式声明

任务涉及网页或桌面 Renderer 时，任务单必须写明：

- `不适用`：没有真实网页或 Renderer 用户路径；
- `组件/DOM`：只证明组件逻辑，不证明真实浏览器键盘、剪贴板、焦点、选择区、导航或生命周期；
- `探索性真实浏览器`：用于一次性探索或登录态操作，结论只能是 `EXPLORATORY_ONLY`；
- `可重复真实浏览器 E2E`：由项目拥有、可无人值守重复执行的真实用户路径，才能作为自动化 E2E AC。

选择可重复真实浏览器 E2E 时，任务单还要固定浏览器和测试版本、服务启停、临时数据库、端口/Context 隔离、稳定 Locator、真实用户动作、后端和重启断言、超时及失败产物。

不能用 jsdom、直接调用编辑器 API、修改 contenteditable 后派发 input、或自造 Clipboard/DataTransfer 来声称完成真实浏览器验收。

## 多层证据

对于跨端、网络或桌面应用，分别报告：

1. 核心/后端协议和网络 E2E；
2. 单元、组件、桥接和持久化测试；
3. 真实桌面、浏览器、移动设备的用户路径和数据回显。

前两层通过不能证明第三层。真实 UI 失败时，保留现场并把失败转成下一任务的红测试或明确环境阻塞。

## 配对、在线和发现

身份配对成功不等于当前在线。若在线状态来自 liveness/last-seen，测试必须分别证明：身份交换、地址/发现、连接、数据发送、接收、回显和重新启动后的恢复。

模拟器的网络能力、局域网组播和真实设备网络不等价；任务单必须写清每种环境实际证明的边界。连接等待、接收循环和 spawned task 都必须有界且可停止。

## 真实证据的最低要求

真实用户路径至少要记录：

- 使用的真实实例和版本；
- 用户动作而非底层 API 直调用；
- 可观察结果；
- 持久化或后端状态；
- 重启/重连后的结果；
- 日志和失败产物路径；
- 所有未覆盖平台的明确状态。
