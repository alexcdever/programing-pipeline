# 执行子代理与审查子代理

## 执行子代理

执行子代理收到的是已提交且冻结的任务单，不是一个可以自由重写的目标。标准循环：

1. 读取任务单和项目规则，确认 task-id、branch、worktree 与允许范围。
2. 为每个行为先写失败测试，真实运行确认失败。
3. 做最小实现使测试通过。
4. 重构、补边界和回归测试，保持全绿。
5. 运行任务单指定的验收命令、构建、lint 和范围检查。
6. 写入当前任务的 `executor-report.md`，列出改动、命令、结果、未完成项和环境限制。

执行子代理不得：

- 修改任务契约、删除困难的验收测试或扩大范围；
- 用 mock 代替任务要求的真实核心、数据库、浏览器或设备链路；
- 把环境缺失写成产品通过；
- 使用其他任务的报告证明当前任务；
- 在主工作树直接改产品代码。

## 审查子代理

审查子代理必须从独立上下文开始，先核对：

- 当前任务单是否已提交；
- worktree 和 branch 是否匹配；
- 当前报告是否属于当前 task-id 且在本轮生成；
- 任务单的每一条验收测试是否有对应测试和证据。

然后独立执行：

1. 读取生产代码、测试正文和差异，而不是只看执行报告。
2. 逐条复跑当前验收测试，包含失败路径、边界、持久化和恢复。
3. 检查实现是否超出允许范围，是否改变未声明的协议、数据格式或用户行为。
4. 检查真实链路要求是否被单元/mock 测试替代。
5. 检查日志是否脱敏、等待是否有界、清理是否幂等、并发和隔离是否成立。
6. 写入当前任务的 `review-report.md`，给出每条验收测试的独立结论。

审查子代理默认只读。无法直接写报告时，必须留下可归属的审查输出，并由主代理按真实来源补齐报告；不能冒充审查子代理写入。

## 主代理最终检查

主代理不能只接收“review PASS”就合并。它必须：

- 重新读取任务身份、Git 状态、worktree 列表和 branch ancestry；
- 检查三份当前任务报告存在、非空、身份正确且内容新鲜；
- 抽查代表性高风险断言；
- 后台监督结果（若存在）只是生命周期证据，不作为验收结论；
- 独立运行关键验收测试、全量测试、构建、lint、差异和冲突检查；
- 将结果写入 `final-check.md` 和任务单进度区；每条验收测试都有当前证据；
- 只有所有验收测试为 PASS 且没有未裁决阻塞时才进入合并。

主代理的最终检查是第三层验证，不应变成“抄 reviewer 的摘要”。
